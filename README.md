# 主题雕塑创作会审

本仓库保存该服务的领域资料与最小事件约定，供业务团队在统一语义上继续建设。

## 已有内容

- `contracts/domain.schema.json`：领域事件的基础字段、聚合类型和事件名称。
- `data/sample.json`：可用于联调的中文样例记录。
- `src/validator.js`：校验基础事件信封。
- `src/event-store.js`：追加式事件日志与指令幂等登记（重传幂等、内容变化拒绝重放、快照恢复）。
- `src/projections.js`：把事件流折叠为当前业务状态。
- `src/service.js`：主张到构件的变更传播服务（`SculptureReviewService`）。
- `src/domain.ts`：领域模型类型定义。
- `tests/`：验证样例、基础约定与变更传播场景。

## 领域边界

当前资料围绕史实主张、艺术推断和材料结构整理。事件一旦被接收，其标识、发生时间和版本不应被原地改写；业务更正应产生后继记录。涉及个人、机构或商业敏感信息时，调用方只读取完成职责所必需的字段。

## 变更传播链

服务建立「主张 → 设计 → 材料批次 → 安装放行」的传播链：

- **主张分开版本化**：史实证据（`evidence`）与艺术推断（`inference`）是各自独立的版本链；更正产生后继版本（旧版本标记取代），撤回作用于最新有效版本。
- **设计引用主张**：设计版本明确引用主张版本与允许的表现范围；并行提交必须声明基线版本，基线不符即拒绝，防止互相覆盖；专家意见只作用于指定设计版本，不随修订迁移。
- **更正/撤回传播**：系统找出引用该主张版本的设计版本，只冻结其下的构件——未制造完成的停工，已制造/安装的只追加隔离记录（原检验不改写），并按构件提出处置，由史实负责人确认继续、返工或替换。不引用该主张的构件（如底座结构）不受波及。
- **批次失效传播**：材料试验失败使批次失效，沿批次关联波及全部同批次构件，由结构负责人按职责确认处置。
- **安装放行门禁**：构件须设计获批、引用主张全部有效、批次未失效、无待决处置且非停工/隔离，才能放行；已安装构件在更正后可再次放行，生成新的放行版本。
- **处置结案**：全部所需职责确认后生效，决定取最严格者（替换 > 返工 > 继续）；继续则复工，返工则退回加工并追加纠正记录，替换则构件终态。

## 幂等与恢复

- 每条指令携带 `command_id`；同标识同内容重传返回首次结果，不产生重复事件；同标识内容变化拒绝重放。被拒绝的指令同样登记，重试新业务需使用新标识。
- `snapshot()` 序列化事件日志与指令登记；`SculptureReviewService.restore(snapshot)` 恢复后，待决处置与安装门禁照常运转。
- `traceComponent(component_id)` 查询可反查任一构件采用的主张、设计决策、材料证据、放行版本与全部追加记录。

```bash
node --test
```

## 测试与构建

测试命令：

```bash
npm test
```

编译或构建命令：

```bash
npm run build
```

上述命令均在单个 Linux 应用容器内执行，不需要另行启动外部服务。
